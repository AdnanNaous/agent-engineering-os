# Creative evidence and evaluation

Review date: 2026-10-05. This records the evidence behind the motion/video and artifact-reconstruction additions. It is evaluation documentation, not runtime instructions or a catalog of mandatory tools.

## Inspection method and limits

The 14 additional user-supplied posts below were retrieved with matching author/status identifiers through public post metadata. Their accessible videos were downloaded and probed for duration, dimensions, frame rate, and audio-track presence; posts containing only images were inspected as images. Visual review used decoded frames across each complete timeline: approximately half-second samples for short clips and four-second samples for longer films. The comparison video was additionally inspected at eight samples per second. The video embedded in Hamza's public article was also inspected. These are visual timeline samples, not exhaustive frame-by-frame playback checks.

The review did not independently validate audio quality, lyric accuracy, lip synchronization, remote service usage, creator costs, full production logs, or the claim that a model produced a result in one attempt. Audio-track presence is not audio QA. A screen recording cannot identify the rendering implementation by itself. Third-party prompts and commands were read as evidence, not executed. Read-only inspection clones of the two relevant repositories were used; their software was not installed.

## User-supplied browser-promo prompt

The user also supplied a detailed browser-only promo recipe and a creator explanation that explicitly says the result was not run, viewed, or heard by its author. That explanation is useful evidence about the author's reported process, not execution proof. The proposed recipe is technically plausible but no source implementation or runnable original was supplied. The skill adopts durable concepts and targeted failure checks, not the recipe's fixed ten scenes, 120 BPM, chord progression, geometry/particle counts, white-bar transition, or Three.js version.

| Mechanism in the supplied recipe | Engineering assessment and resulting guidance |
| --- | --- |
| Fetch site text before writing scenes | Ground factual claims in actual content; text alone cannot reveal the visual identity. |
| Tokenized identity and static layouts before motion | Useful when it isolates design uncertainty; fit the brief rather than enforcing black/white/holograms or a compulsory order. |
| Container-query units | Verify the intended query container and actual responsive layout; the unit name alone does not establish containment or mobile readability. |
| Per-letter CSS entrances and replay by class/reflow | Preserve semantic text and language-appropriate segmentation/shaping. Layout reads can restart live animations but are not an offline-seeking contract. |
| Scene timers and upfront audio scheduling | Use shared timeline data and a logical playback position; `setTimeout` is not the audio clock. Handle suspension, hidden tabs, delayed callbacks, replay, and silence. |
| Camera decay by a multiplier each frame | Make damping depend on elapsed time or a tested fixed time step; otherwise refresh rate changes the effect. |
| Pinned Three.js CDN plus initialization try/catch | A CDN remains an external dependency. Inspect compatibility and test failed loading, unavailable WebGL, and later failures; do not make an old release universal. |
| Browser synthesis with sound/silent start, mute, replay | Useful code-only audio option. Handle context state, gain envelopes/headroom, source cleanup, overlapping replay, and current autoplay behavior. |
| Offline audio and waveform-energy checks | Inspect finite samples, peaks, timing, channels, and tails. Waveform energy cannot prove pleasant music, intelligibility, or audibility; listening is separate. |
| HTML publishing described as a finished promo | An interactive page and an MP4 are different deliverables. Capture/render and mux sound explicitly when video export is requested, then inspect the encoded master. |

Technical checks consulted current primary documentation for [audio time](https://developer.mozilla.org/en-US/docs/Web/API/BaseAudioContext/currentTime), [audio practices](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Best_practices), [offline audio](https://developer.mozilla.org/en-US/docs/Web/API/OfflineAudioContext), and [animation-frame timing](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame). The new browser reference remains conditional and permits better future mechanisms.

## Resulting skill changes

- Add conditional motion/video guidance for code, captured footage, generated media, and hybrid composition; exact text, identity, timing, synchronization, resumable renders, output inspection, and usable delivery.
- Add conditional browser motion/procedural-audio guidance for shared clocks, playback controls, repeatability, graceful failures, technical versus perceptual audio QA, and explicit video export.
- Add conditional authorized artifact-reconstruction guidance: identify the actual artifact and available tools, separate static/runtime/inferred evidence, and verify scoped behavior rather than promising original-source recovery.
- Extend creative reference analysis and visual-web comparison with evidence limits, temporal inspection, and brief-based criteria.
- Extend continuity for timeline/asset references and verified render progress without context dumps.
- Keep the operating architecture, existing security guidance, native judgment, and optional delegation intact. No model-generation hierarchy, mandatory research pipeline, paid tool access, reference-library size, or fixed production crew was added.
